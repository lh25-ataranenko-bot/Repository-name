# План робіт AutoWise

Роботи переструктуровано з 5 етапів концепції у 3 потоки: **сервер і дані**, **сайт**,
**мобільний застосунок**. Сайт і застосунок не мають власної логіки розрахунків: усі
формули (TCO, оцінки, рейтинг, аналіз оголошення) живуть на сервері, тому результати
однакові на будь-якому пристрої.

## Стан на зараз

| Етап | Зміст | Сервер | Сайт | Застосунок |
|------|-------|:------:|:----:|:----------:|
| 1. MVP | Каталог, пошук, фільтри, картки авто, порівняння до 5 машин | ✅ | ✅ | ✅ |
| 2. Аналітика | Калькулятор TCO, рейтинги, графіки, ваги критеріїв | ✅ | ✅ | ✅ (ваги — готові профілі) |
| 3. Дані | Імпорт, перевірка якості, журнал змін, статуси перевірки | ✅ | ✅ адмінпанель | — (не потрібно) |
| 4. Кабінет | Реєстрація, обране, збережені порівняння, гараж | ✅ | ✅ | ✅ |
| 5. Інтелектуальні функції | Розумний пошук, аналіз оголошень | ✅ на правилах | ✅ | ✅ |

## Що залишилося до публічного запуску

### Дані (найбільший обсяг)
- Домовитися з постачальниками ліцензованих даних (каталоги виробників, API характеристик,
  ринкові ціни, історія VIN) і замінити демо-каталог.
- Імпорт XLSX і з API постачальників (зараз — CSV).
- Окремий процес перевірки: редактор переводить модифікацію в «Перевірено» після звірки.
- Фото лише з дозволом використання (зараз — силуети за типом кузова).

### Сервер
- Кешування рейтингу й оцінок (Redis) — зараз оцінки перераховуються на кожен запит,
  що нормально для сотень модифікацій, але не для десятків тисяч.
- Спільне обмеження частоти запитів для кількох екземплярів API (Redis).
- Скидання пароля поштою, підтвердження пошти.
- AI-помічник: замінити `services/query_parser.py` на LLM із тим самим інтерфейсом,
  з обов’язковою умовою відповідати лише на основі бази.
- Історія цін і прогнози (потрібні ринкові дані за період).

### Сайт
- Ручне редагування характеристик в адмінпанелі (API `PATCH /api/admin/cars/{slug}` вже є).
- SEO: карта сайту, мікророзмітка для сторінок авто.

### Мобільний застосунок
- Іконка й заставка AutoWise (зараз стандартні з шаблону Expo).
- Власні ваги категорій у рейтингу (зараз — 6 готових профілів).
- Збірка й публікація через EAS: `npx eas-cli build`, потім `eas submit` у Google Play та App Store.
- Офлайн-режим для гаража.

## Архітектура

```
Браузер ──► Next.js (web) ──/api/*──► FastAPI (backend) ──► PostgreSQL
Телефон ──► Expo (mobile) ──────────► FastAPI (backend)
```

Обробка запиту порівняння (як у концепції, розділ 9.1): клієнт надсилає ідентифікатори
модифікацій → API перевіряє запит і завантажує дані → нормалізує одиниці → модуль
порівняння будує таблицю й оцінки → сервер повертає структурований результат → інтерфейс
показує таблицю, графіки й пояснення.
